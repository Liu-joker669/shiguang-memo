# 拾光 Memo 产品说明与决策记录

## 1. 产品定位

拾光 Memo 是面向大学生考前复习的课程资料工作台 Demo。目标不是替代通用笔记软件，而是缩短“发现薄弱知识点后重新找到原资料”的路径。

当前核心假设：当诊断结果能够直接指向对应资料时，学生回看和核对内容的成本会降低。该假设尚未经过真实用户研究或学习效果实验验证。

## 2. 目标用户与场景

- 目标用户：课程资料较多、临近考试需要集中复习的大学生；
- 核心场景：资料分散、复习重点不清楚、问答结果难以核对来源；
- 非目标场景：长期科研知识管理、团队文档协作、开放领域问答。

## 3. MVP 闭环

1. 用户批量选择课程文件，或使用文本粘贴兜底入口；
2. 系统在浏览器本地提取文字，自动预填标题、课程分类、标签、摘要和复习要点；
3. 用户确认信息后导入资料库；
4. 系统依据要点生成规则诊断题；
5. 答错后回到对应原始资料；
6. 用户提出问题，系统检索相关资料并显示来源；
7. 无相关资料时明确提示无结果，不生成推测答案。

## 4. 当前实现与模拟能力

### 已实现

- 文字型 PDF、`.docx`、TXT、Markdown 批量导入和本地持久化；
- PDF 文字坐标排序、页码过滤、常见数学符号修复和解析质量提示；
- 标题、分类、标签、摘要和复习要点的本地规则预填；
- 扫描版 PDF、旧版 `.doc`、超大文件等异常状态提示；
- 共享资料状态贯通资料、卡片、诊断、问答和详情；
- 中文关键词检索和来源跳转；
- 诊断得分、待回看资料和重新测验；
- 无结果、资料不足等基础异常状态。

### Demo 模拟

- “自动总结”是文本截取和列表识别规则；
- “资料问答”是关键词检索和固定模板；
- “诊断题”由不同资料的要点组合生成；
- 文件读取进度用于表达真实的本地解析状态。

### 尚未实现

- 扫描版 PDF OCR、旧版 `.doc` 解析和图片文字识别；
- 文本切块、Embedding、向量检索和重排；
- LLM 生成、提示词治理与模型评测；
- 页码级引用、账号体系、云同步和埋点平台；
- 真实用户访谈、可用性测试与学习效果验证。

## 5. 关键产品规则

- 问答必须返回至少一个本地资料来源，否则显示无结果；
- 诊断题必须保留来源资料 ID，答错后可以直接回看；
- 用户导入的数据只保存在当前浏览器，不上传服务器；
- 一次最多读取 5 份、单份不超过 20 MB，PDF 最多整理前 80 页，正文最多保存前 8 万字；
- 发现数学私有区字符时只修复经过验证的常见符号；复杂公式、数轴或图片必须提醒用户对照原 PDF；
- Demo 能力必须在界面和文档中明确标注，不使用真实 AI/RAG 成果表述。

## 6. 下一步验证

1. 邀请 5 名近期有考试任务的大学生完成“导入—诊断—回看—提问”任务；
2. 记录任务完成率、找到来源所需时间、错误理解与退出位置；
3. 判断用户更需要“自动出题”还是“快速找出处”；
4. 只有当流程价值成立后，再评估真实 RAG 的工程投入。
